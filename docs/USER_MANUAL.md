## 1. 系統概述

**mf-topomon** 是一個基於 LLDP（Link Layer Discovery Protocol）的網路拓撲監控系統，提供：

- 🗺️ **即時拓撲圖** - 視覺化網路設備連接關係
- 📊 **設備監控** - CPU、記憶體、連接狀態監控
- 🚨 **智慧告警** - 級聯離線偵測與根本原因分析
- 👥 **群組管理** - 按區域/功能分組設備
- 🌐 **多語系介面** - 支援繁中/簡中/英文

### 技術架構

| 層級 | 技術 |
|-----|-----|
| 前端 | HTML5 + CSS3 + JavaScript (vis.js) |
| 後端 | Python FastAPI |
| 資料庫 | SQLite |
| 協定 | SNMP v2c (LLDP-MIB) |

## 2. 快速開始

### 2.1 系統需求

- Python 3.9+
- 現代瀏覽器 (Chrome, Firefox, Edge)
- 網路設備需支援 SNMP 和 LLDP

### 2.2 安裝步驟

> 正式部署不用照這一節做 —— 一行指令就好，見
> [docs/DEPLOYMENT.md](DEPLOYMENT.md)：
>
> ```bash
> curl -fsSL https://raw.githubusercontent.com/nox913106/net-lldp-topo/main/scripts/bootstrap.sh | sudo bash
> ```
>
> 下面是在自己機器上跑一份來看的步驟。


```bash
# 1. 複製專案
git clone https://github.com/nox913106/net-lldp-topo.git
cd net-lldp-topo

# 2. 建立虛擬環境
python -m venv venv
.\venv\Scripts\activate  # Windows
source venv/bin/activate  # Linux/Mac

# 3. 安裝依賴
pip install -r requirements.txt

# 4. 初始化資料庫
python -c "from app.db import init_db; init_db()"

# 5. 啟動伺服器
uvicorn app.main:app --host 0.0.0.0 --port 8080
```

### 2.3 存取系統

開啟瀏覽器前往安裝時印出的網址（`https://<主機>/`），用安裝時印出的 `admin`
帳密登入。第一次登入會要求換成你自己的密碼。開發用的起法沒有帳號，先建一個：
`python -m app.cli set-password admin`。

## 3. 功能說明

### 3.1 拓撲圖

拓撲圖是系統的核心功能，提供網路架構的視覺化呈現。

#### 視圖模式

| 模式 | 說明 |
|-----|-----|
| **總覽 (Overview)** | 顯示所有設備，自動佈局 |
| **完整地圖 (Full Map)** | 完整拓撲，可縮放平移 |
| **群組視圖 (Group View)** | 依群組篩選顯示設備 |

#### 設備圖示

| 圖示 | 類型 | 說明 |
|-----|-----|-----|
| 🟢 | 線上設備 | 正常運作中 |
| 🔴 | 離線設備 | 無法連接 |
| 🟡 | 警告狀態 | 效能指標偏高 |

#### 操作方式

- **點擊設備** → 顯示設備詳情面板
- **雙擊設備** → 開啟完整詳情彈窗（含階層資訊）
- **拖曳設備** → 調整設備位置
- **滾輪縮放** → 放大/縮小拓撲圖
- **右鍵拖曳** → 平移視圖

#### 設備詳情彈窗

雙擊設備後會顯示：

- **設備資訊**: IP 位址、類型、品牌、型號、韌體、CPU/記憶體使用率
- **上游設備**: 此設備連接的上層設備清單
- **下游設備**: 此設備管理的下層設備清單
- **活躍告警**: 與此設備相關的未解決告警

---

### 3.2 設備管理

進入 **設備 (Devices)** 頁面管理所有網路設備。

#### 設備列表功能

| 功能 | 說明 |
|-----|-----|
| **搜尋** | 依主機名稱或 IP 位址篩選 |
| **狀態篩選** | 線上 / 離線 / 未知 |
| **品牌篩選** | Cisco / HP / Juniper 等 |
| **排序** | 點擊表頭進行升降序排序 |
| **分頁** | 調整每頁顯示筆數 |

#### 新增設備

1. 點擊 **「+ 新增設備」** 按鈕
2. 填寫設備資訊：
   - **Hostname**: 設備名稱
   - **IP Address**: 管理 IP
   - **Vendor**: 設備品牌
   - **Device Type**: 設備類型（核心、分發 = L3 交換機；接入、TOR = L2 交換機；路由器、防火牆、無線基地台、監視攝影機、負載平衡器、伺服器、虛擬機）。拓樸圖上每種類型有自己的圖示；自動探索到的設備會先依主機名稱猜一次（例如 `cam-`、`lb-`、`srv-`、`vm-`），之後可在這裡改
   - **SNMP Community**: SNMP 社群字串
   - **Alert Profile**: 告警設定檔
3. **Auto-discover neighbors** 選項：
   - ✅ 勾選：自動透過 LLDP 發現並新增鄰居設備
   - ❌ 不勾選：僅新增此設備
4. 點擊 **「儲存」**

#### 編輯/刪除設備

- **編輯**: 點擊設備列的 ✏️ 按鈕
- **刪除**: 點擊設備列的 🗑️ 按鈕

### 3.3 告警中心

進入 **告警 (Alerts)** 頁面查看系統告警。

#### 告警類型

| 類型 | 嚴重程度 | 說明 |
|-----|---------|-----|
| **設備離線** | Critical | 設備無法通過 SNMP 連接 |
| **CPU 過高** | Warning/Critical | CPU 使用率超過閾值 |
| **記憶體過高** | Warning/Critical | 記憶體使用率超過閾值 |
| **連結使用率過高** | Warning/Critical | 網路介面使用率超過閾值 |

#### 級聯離線偵測

系統會自動分析設備階層，判斷離線原因：

- **根本原因告警 (Root Cause)**: 標記為 `ROOT CAUSE`，表示此設備直接導致其他設備離線
- **受影響設備**: 因上游設備離線而無法連接的設備
- **抑制告警**: 已確認且暫時抑制通知的告警

#### 告警卡片分組

告警列表會自動分組顯示：

| 分組 | 說明 |
|-----|-----|
| 🔥 **根本原因告警** | 被識別為離線根因的告警，優先處理 |
| 🔕 **已抑制告警** | 已確認並暫時抑制通知的告警 |
| ⚠️ **一般告警** | 其他未分類的告警 |

---

#### 告警確認管理

告警確認是處理告警的主要方式，可記錄處理人員和原因。

##### 確認告警

1. 點擊告警卡片或告警詳情視窗中的 **「✓ Acknowledge」** 按鈕
2. 在彈出的確認視窗中填寫：
   - **確認原因** (必填): 描述處理狀況或計畫
   - **抑制通知時間** (選填): 設定暫時不再收到此告警的通知
3. 點擊 **「Confirm」** 完成確認

##### 通知抑制功能

確認告警時可選擇抑制通知：

| 抑制時間選項 | 說明 |
|-------------|-----|
| 不抑制 | 持續接收此告警通知 |
| 1 小時 | 抑制 1 小時內的重複通知 |
| 4 小時 | 抑制 4 小時內的重複通知 |
| 24 小時 | 抑制 24 小時內的重複通知 |
| 永久 | 永不再發送此告警通知 |

> 💡 **提示**: 抑制通知不會關閉告警，只是暫停通知。告警解決後仍會自動恢復。

##### 新增備註

對於已確認的告警，可以添加後續處理備註：

1. 開啟告警詳情視窗
2. 點擊 **「📝 Add Note」** 按鈕
3. 輸入備註內容
4. 備註會記錄在確認歷史中

---

#### 確認歷史管理

每個告警都有獨立的確認歷史記錄，可追蹤所有處理過程。

##### 查看歷史

1. 點擊告警卡片開啟詳情視窗
2. 在 **「✅ Acknowledge History」** 區塊查看所有歷史記錄

##### 歷史記錄內容

每筆記錄包含：
- **事件類型**: ACKNOWLEDGE（確認）、ADD_NOTE（備註）、EDIT（編輯）、DELETE（刪除）
- **時間戳記**: 操作時間
- **原因/內容**: 確認原因、備註內容或編輯說明
- **抑制狀態**: 若有設定抑制，顯示抑制到期時間

##### 編輯歷史記錄

1. 在歷史記錄項目中點擊 **「📝 Edit」** 按鈕
2. 在彈出的輸入視窗中修改內容
3. 點擊 **「Confirm」** 儲存

##### 刪除歷史記錄

1. 點擊 **「🗑️ Delete」** 按鈕
2. 輸入刪除原因（必填）
3. 選擇是否恢復通知（若原記錄有抑制設定）
4. 確認刪除

> ⚠️ **注意**: 刪除操作為軟刪除，記錄會被標記為「已刪除」並顯示刪除原因，但不會完全移除。

##### 恢復推播通知

若告警已被抑制通知，可手動恢復：

1. 在確認歷史區域找到抑制資訊
2. 點擊 **「▶️ Resume Notifications」** 按鈕
3. 確認恢復後，系統將重新發送此告警的通知

---

#### 告警詳情視窗

點擊告警卡片開啟詳情視窗，包含：

| 區塊 | 內容 |
|-----|-----|
| 🖥️ **設備** | 設備名稱、IP 位址 |
| 📋 **訊息** | 告警詳細訊息 |
| ⏰ **時間軸** | 觸發時間、當前狀態 |
| ✅ **確認歷史** | 所有確認和操作記錄 |

#### 告警操作總覽

| 操作 | 說明 |
|-----|-----|
| **確認告警** | 輸入原因並可選擇抑制通知時間 |
| **新增備註** | 為已確認告警添加處理備註 |
| **編輯記錄** | 修改歷史記錄內容 |
| **刪除記錄** | 軟刪除歷史記錄（保留刪除原因） |
| **恢復推播** | 取消通知抑制，恢復告警通知 |
| **查看詳情** | 開啟完整告警資訊視窗 |
| **前往拓撲** | 在拓撲圖中定位該設備 |

### 3.4 群組管理

進入 **群組 (Groups)** 頁面組織設備。

#### 建立群組

1. 點擊 **「+ 新增」** 按鈕
2. 填寫群組資訊：
   - **名稱**: 群組顯示名稱
   - **描述**: 選填說明
   - **父群組**: 建立階層結構
   - **顏色**: 在拓撲圖中的標識顏色
3. 點擊 **「儲存」**

#### 把設備放進群組

設備一開始不屬於任何群組，所以都在左側最下面的 **「未分配」** 裡：

1. 點 **「未分配」**，右側列出還沒有群組的設備
2. 勾選要放進去的設備
3. 在下方的 **「移動到…」** 選擇目標群組，按 **「移動」**

#### 管理群組設備

1. 在左側選擇群組，右側顯示該群組的設備與目前狀態
2. 勾選設備之後可以：
   - **移動**: 移到另一個群組
   - **從群組移除**: 設備回到「未分配」（設備本身不會被刪除）
3. 右上角的 **「編輯」** 可以改名稱、描述、父群組與顏色；**「刪除」** 只刪
   群組 —— 裡面的設備回到「未分配」，子群組往上移一層

#### 群組視圖

在拓撲圖頁面選擇 **「群組視圖」**，可依群組篩選顯示設備。

### 3.5 系統設定

進入 **設定 (Settings)** 頁面配置系統。

#### 系統概覽

顯示當前系統狀態：
- 設備總數
- 活躍告警數
- 連結總數

#### SNMP 設定

這一區的設定存在伺服器上（`settings.json`），而且伺服器會照著做：

| 設定項目 | 預設值 | 說明 |
|---------|-------|-----|
| 預設社群字串 | public | 給「定期掃描網段」使用。每台設備保留它被加入時的 community |
| 允許的網段 | （空） | 每行一個 CIDR。空白表示不限制 |
| 啟用網段限制 | 關 | 開啟後，SNMP 測試、手動探索、網段掃描，以及收集器沿著 LLDP 鄰居自動發現，都**不會**對網段外的位址送 SNMP |
| 定期掃描這些網段 | 關 | 開啟後每隔「掃描間隔」逐一詢問網段裡的位址（每個網段最多 256 個），有回應的就加入 |
| 掃描間隔 | 3600 秒 | 300–86400 秒 |

> **為什麼要開網段限制**：鄰居就是線的另一頭接著的東西 —— 可能是 ISP 的
> 路由器或別的單位的交換機。對它做自動發現，等於把你的 community 送給它。

「逾時 / 重試次數」是唯讀的：它們與輪詢間隔都是啟動時的設定，在設定檔裡
（`SNMP_TIMEOUT`、`SNMP_RETRIES`、`COLLECTOR_INTERVAL`、
`COLLECTOR_FAST_INTERVAL`），改完執行 `sudo mf-topomon restart`。收集器實際
用的間隔顯示在同一頁的「收集器狀態」。

#### 告警設定檔

管理告警閾值設定：

| 指標 | 警告閾值 | 嚴重閾值 |
|-----|---------|---------|
| CPU 使用率 | 80% | 95% |
| 記憶體使用率 | 85% | 95% |
| 連結使用率 | 70% | 90% |

**建立新設定檔**:
1. 點擊 **「+ 新增設定檔」**
2. 設定名稱和各項閾值
3. 點擊 **「儲存設定檔」**

#### 日誌匯出

顯示目前的狀態（關閉，或匯出到哪裡）。它是啟動時的設定，在 `.env` 裡：
`LOG_EXPORT_ENABLED`、`LOG_EXPORT_TYPE`（`elasticsearch` 或 `graylog`）、
`ELASTICSEARCH_URL` 或 `GRAYLOG_HOST` / `GRAYLOG_PORT`，改完執行
`sudo mf-topomon restart`。

#### 通知設定

| 設定 | 說明 |
|-----|-----|
| 聲音警報 | 拓樸圖或告警頁開著的時候，出現**新的**告警就在這個瀏覽器播放提示音（嚴重與警告的聲音不同）。設定存在瀏覽器裡，每個瀏覽器各自決定 |

### 3.6 登入與後台

#### 登入

每一頁都要登入。帳號有兩種：

- **本機帳號**：密碼存在系統裡（scrypt 雜湊）。安裝時建立的 `admin` 是其中之一。
- **AD 帳號**：用公司的 AD 帳密登入，系統不保存 AD 密碼。要先在「後台 → AD 驗證」設定。

右上角是帳號選單：變更密碼（本機帳號）、後台（系統管理員）、登出。閒置 8 小時、
或登入滿 7 天會自動登出；連續輸入錯誤密碼 5 次，帳號會鎖 15 分鐘。

#### 角色

| 角色 | 可以做的事 |
|---|---|
| 系統管理員 | 全部，包含後台 |
| 維運人員 | 新增／修改／刪除設備與群組、告警設定檔、SNMP 設定、確認告警、手動探索、SNMP 測試工具 |
| 檢視者 | 只能看 |
| 訪客 | AD 帳號第一次登入時的角色：什麼都看不到，等系統管理員在「帳號管理」給角色 |

#### 後台

系統管理員從右上角選單（或導覽列的「後台」）進入。九個分頁：

| 分頁 | 內容 |
|---|---|
| **系統狀態** | 健康檢查：收集器有沒有在回報、資料是不是最新、備份夠不夠新、憑證多久到期、磁碟用量、通知有沒有送出去。每 6 小時自動跑一次，有異常時發通知（同樣的問題一天最多通知一次）。「主機完整健檢」以 root 跑 `mf-topomon doctor`。 |
| **帳號管理** | 新增本機帳號或預先登錄 AD 帳號、改角色、停用、重設密碼、全部登出、刪除。最後一個系統管理員（以及最後一個本機系統管理員）不能被刪除或降級。下方是登入規則（閒置登出、鎖定）。 |
| **AD 驗證** | 伺服器網址（一行一台，連不上時換下一台）、網域、Base DN、允許登入的群組（含巢狀群組）、第一次登入的角色、LDAPS 用的公司 CA 憑證。**先按「測試」**：它會一步一步回報網路、TLS、帳號、群組，而且不會儲存。 |
| **稽核紀錄** | 所有變更（設備、群組、設定、帳號、確認告警、備份、升級……）以及登入、登入失敗、登出。可依日期、動作、操作者、關鍵字查詢，匯出 CSV（Excel 直接開得了中文）。密碼與 community 等欄位一律遮掉。紀錄不能修改或刪除，只會在超過保存天數（預設 365 天）後被清除。 |
| **通知** | 通道：Microsoft Teams（Workflows 或 Incoming Webhook 的網址）、Webhook（JSON，可設簽章密鑰）、Email（SMTP）。每個通道選要送哪些事件（新告警、恢復、健康檢查、工作完成）與最低等級。「發送測試」立刻送一則測試訊息。同一輪超過 5 則（可調）會合併成一則彙整。下方可以改訊息範本，以及看發送紀錄與重送失敗的訊息。 |
| **備份還原** | 排程（每天或每週、幾點、保留幾份）、立即備份、下載（要再輸入一次自己的密碼）、還原（要輸入 RESTORE 與自己的密碼；會先自動備份現在的狀態，服務會重新啟動，所有人要重新登入）、刪除。 |
| **HTTPS 憑證** | 目前憑證的主體、簽發者、到期日與指紋；上傳新的憑證、私鑰（不能有密碼）與中繼憑證。換上之前會先檢查，nginx 不接受就換回原本的。 |
| **系統資訊** | 每次打開都即時從主機讀：硬體、作業系統、服務狀態、資料庫版本與大小、磁碟、收集器設定、Python 套件版本（與 requirements.txt 對不上的會標出來）。可下載 JSON。 |
| **版本與升級** | 目前版本與最近的變更；「檢查更新」列出有哪些新版本；「升級到最新版」等同 `sudo mf-topomon upgrade`（先備份、健康檢查沒過自動回滾），頁面會顯示進度並自己重新連線。 |

備份、還原、升級、HTTPS 憑證與主機完整健檢需要 root：應用程式只送出請求，由
主機上的背景執行器以 root 驗證後執行。Docker 部署沒有背景執行器，這幾項請用
主機上的 `mf-topomon-docker` 指令。

#### 進不去了

忘記密碼、帳號被鎖、AD 故障、所有管理員都被降級 —— 在主機上：

```bash
sudo mf-topomon password          # 重設 admin，印出隨機密碼，登入時要換
```

## 4. 進階功能

### 4.1 多語系介面

系統支援三種語言介面，可在設定頁面手動切換。

#### 支援語言

| 語言代碼 | 顯示名稱 |
|---------|---------|
| `en` | English |
| `zh-TW` | 繁體中文 |
| `zh-CN` | 简体中文 |

#### 切換語言

1. 進入 **設定 (Settings)** 頁面
2. 在 **「外觀設定」** 區塊找到 **「語言」** 選項
3. 從下拉選單選擇目標語言
4. 頁面會立即切換語言

> 💡 **提示**: 語言偏好會儲存在瀏覽器的 localStorage 中，下次訪問時自動套用。

#### 翻譯範圍

所有介面元素皆已翻譯，包括：
- 導覽選單（拓樸 / 設備 / 告警 / 群組 / 設定）
- 按鈕文字和標籤
- 表格標題
- 彈出視窗內容
- 動態訊息和提示

### 4.2 深色/淺色模式

系統支援兩種配色，版面相同（軍規戰術風格：四角準星框、座標方格、雷達掃描）：

- **深色 · 隱形黑曜軍灰**（預設）：適合機房、牆面大螢幕
- **淺色 · 北約戰術粉筆白**：適合明亮的辦公室，狀態色加深以維持對比

狀態色在兩種模式意義相同：綠色正常、琥珀色需要注意、紅色斷線或嚴重告警。
系統若設定為「減少動態效果」，雷達掃描與連線流動動畫會自動停止。

#### 切換主題

1. 進入 **設定 (Settings)** 頁面
2. 在 **「外觀設定」** 區塊找到 **「主題」** 選項
3. 選擇 **「🌙 Dark · Obsidian」** 或 **「☀️ Light · Chalk」**

### 4.3 SNMP 測試工具

設定頁面提供內建的 SNMP 測試工具，可在新增設備前先驗證連線。

#### SNMP 連線測試

1. 進入 **設定 (Settings)** 頁面的 **「SNMP Testing Tools」** 區塊
2. 填寫測試參數：
   - **Target IP**: 目標設備 IP
   - **Community String**: SNMP 社群字串
   - **OID**: 選擇要查詢的 OID（或自訂）
3. 點擊 **「SNMP Get」** 或 **「SNMP Walk」** 執行測試
4. 檢視測試結果

#### 可用 OID 選項

| OID | 說明 |
|-----|-----|
| sysDescr | 系統描述 |
| sysName | 主機名稱 |
| sysUpTime | 運行時間 |
| lldpRemTable | LLDP 鄰居表 |
| 自訂 OID | 輸入任意 OID |

#### 網段限制

可設定允許的 SNMP 測試目標網段：

1. 在 **「SNMP 設定」** 區塊填寫允許的網段（CIDR 格式）
2. 勾選 **「啟用網段限制」**，按 **「儲存 SNMP 設定」**
3. 之後對網段外的 IP 做測試或探索，伺服器會直接拒絕並說明原因

這個限制是伺服器端的，對所有人、所有入口（包含直接呼叫 API）都有效。

### 4.4 手動設備探索

可手動觸發設備探索，無需在設備列表中逐一新增。

#### 使用方法

1. 在 **「Manual Device Discovery」** 區塊填寫：
   - **IP Address**: 起始設備 IP
   - **Community String**: SNMP 社群字串
2. 勾選 **「Recursive Discovery」** 啟用遞迴探索（自動發現 LLDP 鄰居）
3. 點擊 **「🔎 Start Discovery」**
4. 系統會顯示發現的設備清單，包括新增/已存在狀態

### 4.5 API 存取

系統提供 RESTful API，可透過程式化方式存取：

```
GET  /api/v1/devices          - 取得設備清單
GET  /api/v1/topology         - 取得拓撲資料
GET  /api/v1/alerts           - 取得告警清單
POST /api/v1/devices          - 新增設備
PUT  /api/v1/devices/{id}     - 更新設備
DELETE /api/v1/devices/{id}   - 刪除設備
```

API 文件：`https://<主機>/docs`（要先登入）。

程式呼叫 API 的方式跟瀏覽器一樣：先 `POST /api/v1/auth/login`（JSON：
`username`、`password`）拿到 cookie，之後的請求帶著它；會改東西的請求
（POST／PUT／DELETE）另外要帶 `X-Requested-With` 標頭（任何值），否則回 403。

```bash
curl -k -c jar -H 'X-Requested-With: script' -H 'Content-Type: application/json' \
     -d '{"username":"noc","password":"…"}' https://<主機>/api/v1/auth/login
curl -k -b jar https://<主機>/api/v1/devices
```

建議給程式一個專用的**檢視者**帳號：它讀得到一切，但改不了任何東西。

## 5. 常見問題

### Q1: 設備顯示離線但實際可連接？

**可能原因**:
1. SNMP 社群字串設定錯誤
2. 防火牆阻擋 SNMP 埠 (UDP 161)
3. 設備 SNMP 服務未啟用

**解決方法**:
1. 確認設備的 SNMP 設定
2. 檢查網路防火牆規則
3. 使用 `snmpwalk` 測試連線

### Q2: 拓撲圖沒有顯示連接線？

**可能原因**:
1. 設備未啟用 LLDP
2. LLDP 鄰居表尚未建立
3. 未執行自動發現

**解決方法**:
1. 確認設備已啟用 LLDP
2. 等待幾分鐘讓 LLDP 交換資訊
3. 重新執行設備發現

### Q3: 告警確認後仍顯示活躍？

**說明**: 確認告警只是標記已處理，並不會關閉告警。告警會在問題解決後自動轉為「已恢復」狀態。

### Q4: 如何備份資料？

**方法**: 「後台 → 備份還原」：預設每天 02:30 自動備份、保留 14 份，也可以
按「立即備份」或在主機上 `sudo mf-topomon backup`。備份包含資料庫（設備、
設定、帳號、稽核紀錄、通知設定）與主機上的設定檔，見
[DEPLOYMENT.md](DEPLOYMENT.md)「備份與復原」。
