mf-topomon

網路拓撲是設備自己說出來的。這套東西只負責問對問題、問得夠勤，並且在它壞掉的時候講實話。

以 LLDP／CDP 自動發現與繪製交換機之間的實際佈線，逐條線路監看 up／down 與流量， 並在設備端不需要任何設定改動的前提下接收 SNMP trap。 設計目標是 500 台規模下仍然可解釋：每一個延遲、每一次 CPU 佔用，都量過並寫在文件裡。

  • LLDP / CDP
  • SNMP v1 / v2c / v3
  • FastAPI + PostgreSQL
  • Docker Compose
  • zh-TW / zh-CN / EN

問題

一張靠人維護的網路圖，從畫完的那一刻就開始過期

交換機之間誰接誰、接在哪個埠、那條線現在是不是通的 —— 這些事設備本來就透過 LLDP／CDP 互相廣告。問題從來不是資料不存在，而是沒有人持續去問， 以及問到的東西沒有被拿去跟告警對上。

mf-topomon 把這件事收斂成兩個週期不同的輪詢迴圈，加上一個可選的 trap 接收器。 拓樸由設備回報的 sysName 配對出來，所以它跟 IP、跟 DNS、 跟誰在哪個網段都無關。

核心

兩個迴圈，因為「誰接誰」和「它還活著嗎」不該同一個頻率

有人去機房移一條線，那是以天或週計的事件；一條 uplink 掛掉，是以秒計的事件。 用同一個間隔去問這兩件事，只會讓其中一個又慢又貴。

Trap

設備端不用加任何設定

trap 最常見的卡關是來源位址：設備從出口介面送出通知，來源位址不是你輪詢它的那個 管理位址，於是收到的人認不出是誰送的。慣例做法是去每一台設備上加 snmp-server trap-source。

這裡的做法是反過來：盤點時順便走訪設備自己回報的所有 IP 位址， 所以從任何一個介面送出的 trap 都認得出來。那次走訪量過是一次輪詢的 5.2%（5.01 ms 對 95.6 ms），而每台設備最多每小時走訪一次， 所以平均每輪只付十二分之一。

  • 比對順序是封包來源位址優先，v1 的 snmpTrapAddress 只是最後手段 —— 偽造的宣稱蓋不過真實來源。
  • 位址只從輪詢學來，沒有人宣稱得到。
  • trap 永遠不是唯一的事實來源：快迴圈仍然會重新確認一次。

告警抑制：三個旋鈕，用「晚一點但確定」換「掉包一次就叫人起床」

ALERT_OFFLINE_CONFIRM_CYCLES

連續幾輪沒回應才算離線。設 3 配 60 秒快迴圈 ≈ 要安靜三分鐘，一次擁塞吃掉三個 SNMP 嘗試就不再叫人。

ALERT_LINK_FLAP_TRANSITIONS

一條線在時間窗內跳動超過這個次數就算 flapping：告警被按住不反覆開關，而且會說它在跳。第一次 down 永不延遲。

ALERT_TRAP_REQUIRES_POLL

trap 要不要等下一輪輪詢同意才告警。開了之後，遺失、過期或偽造的 trap 都叫不動人，代價是最多一個快迴圈。

up flapping（抑制中） down
抑制狀態留在收集器行程的記憶體裡，但會寫進它自己的 heartbeat，所以設定頁看得到「現在有幾台在確認中、幾條線被按住」。

裝 docker、取原始碼、產生隨機密鑰與登入密碼、起服務、等到 /health/ready 回答「資料庫也連得上」為止，然後印出網址與帳密。 重複執行等同一次更新，不會動到設定、憑證與資料庫。

topomon health

逐層檢查容器、代理、認證、資料庫、收集器心跳，全過才 exit 0 —— 可以直接丟給 cron 或監控。

topomon update

拉最新版、重建、健康檢查。沒過就自動回滾到更新前那個 commit 再起一次，並印出失敗日誌。

topomon backup / restore

資料庫 dump 與復原（復原要打字確認）。預設保留最近 14 份。

topomon logs / status / password

跟著看任一服務的日誌、看收集器完整回報、重設介面密碼（立即生效，不用重啟）。

安全

認證在反向代理上，而且有測試守著

這套系統沒有使用者的概念，也刻意不發明一套 —— 要保護的是「誰連得到這個管理介面」，因為 API 讀得到每一台設備的明文 community。 一層 HTTP basic auth 就夠，而放在代理上意味著應用程式之後怎麼改都不會把這層弄丟。

  • 應用程式的 8080 與資料庫的 5432 只綁 127.0.0.1，唯一入口是代理的 443。
  • 80 一律轉到 443，而且在問密碼之前就轉 —— basic auth 是 base64，不是加密。
  • /docs 也要密碼：那是可以直接打 API 的表單。
  • 只有 /health 與 /health/ready 免認證，給負載平衡器與健康檢查用。

這個設定檔是整個專案的認證，而「只有人會讀的設定檔」是最容易漂掉的東西。 所以有 8 項測試會起一個真的 nginx、餵它部署出去的那一份設定、 後面接一個會記錄「我被要求了什麼路徑」的假應用程式，用來證明 沒帶密碼的請求根本到不了應用程式 —— 不只是「回了 401」。

證據

這個專案被依賴漂移咬過一次，所以測試的是筆數

部署出去的某個版本在 pysnmp 的 asyncio 進入點換掉之後，LLDP 走訪變成 回傳 0 筆、不丟任何錯誤 —— 從外面看就只是拓撲圖空白。 型別檢查抓不到那件事，鎖定版本能讓它不再自己變動， 但真正能證明「走訪還活著」的只有一個會去問真 agent 的測試。

限制

還沒做到的事

這一節跟上面幾節一樣重要：不寫下來的限制，使用者會在最糟的時候自己發現。

沒有在真設備上跑過
所有證據都來自 snmpsim 的錄製（錄製本身取自真設備）。「某家廠商的韌體在某個 OID 回了奇怪的東西」這類事，只有接上真設備才會知道。
沒有真正的 schema migration
啟動時會自動補上新增的可為 NULL 欄位與索引；改型別、刪欄位、加 NOT NULL 欄位不會自動做，只會在日誌留一行警告。
即時推送尚未實作
前端是輪詢的。WebSocket 要成立缺的不是端點，而是一條從收集器行程到 API 行程的路。
Redis 還沒被用到
它在 compose 裡，但程式目前沒有在用它。拓樸回應快取是下一步之一。
整個部署流程沒有被端對端跑過一次
安裝腳本的語法、設定檔、compose 都被測過，但「在一台真機器上從零裝到好」還沒有。第一次上線請先在測試機跑一遍。
